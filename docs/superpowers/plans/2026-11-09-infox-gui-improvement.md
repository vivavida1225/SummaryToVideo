# InfoX 이후 GUI 개선 계획

## 1. 목표와 방향

**상단의 MyAsset 불러오기·원문 수집·대본 미리보기와 편집은 유지하고, InfoX 이하를 ‘현재 단계와 다음 행동’ 중심으로 재구성한다.**

첨부 화면과 현재 코드에서 확인한 문제는 다음과 같다.

- 장면별 검사·교체 계획·저장 검증·게시 기록이 연속으로 펼쳐져 화면이 길어진다.
- 필수 진행 버튼과 보조 조회 버튼의 스타일이 같아 중요도를 구분하기 어렵다.
- 제작 진행률과 여러 상태가 일반 문장으로 표시된다. 게시 영역에는 이미 진행 막대가 있지만 표현이 통일되어 있지 않다.

선택한 방향은 **PC 우선 단계형 작업 패널**이다. 단순 접기보다 다음 행동을 명확히 보여주고, 탭보다 전체 흐름을 쉽게 파악하도록 한다. 전송본 확정과 제작 시작은 한 버튼으로 통합한다.

## 2. 화면 구성과 정보량

InfoX 영역을 아래 네 단계로 구성한다.

| 단계 | 기본으로 보여줄 내용 | 주요 행동 |
|---|---|---|
| ① 제작 준비 | 영상 제목, 자동 대체 옵션, 제작 설정 요약, 필요한 검토 확인 | **InfoX 영상 제작 시작** |
| ② 자동 제작 | 현재 처리 단계, 진행 표시, 에셋 검사·교체 결과 요약 | 정상 진행은 자동, 중단 시 필요한 조치 |
| ③ 편집 및 게시 | 편집기 열기, 편집·저장 안내, 게시 기준일, 제목·설명, 일부공개 설정, 이용량 | **편집 완료 · 렌더 및 유튜브 업로드** |
| ④ 완료 | 검증된 영상 링크, 링크 복사 결과, 파일 저장 결과 | 링크 다시 복사·파일 다운로드 |

- **PC:** 왼쪽은 현재 단계의 작업 내용, 오른쪽은 현재 상태·다음 행동·주요 버튼을 배치한다. 오른쪽 요약은 InfoX 영역 안에서 스크롤을 따라온다.
- **860px 이하:** 한 열로 배치하고 현재 상태와 주요 버튼을 상세 기록보다 먼저 보여준다.
- 완료 단계는 한 줄 요약으로 접고, 이후 단계는 제목과 대기 상태만 표시한다. 사용자가 펼친 이전 기록은 폴링 때문에 다시 접지 않는다.
- 오류·확인 필요 상태는 해당 단계에 원인과 조치를 즉시 노출한다.

정보는 다음 기준으로 정리한다.

| 항상 노출 | 기본 접기 |
|---|---|
| 현재 단계, 다음 행동, 차단 사유 | 영상·작업 ID, 서버 버전, 기술적 처리 기록 |
| 검사·교체 개수, 확인 불가 개수 | 장면별 전체 검사 결과와 메타데이터 근거 |
| 현재 게시 설정과 예상 이용량 | 이전 게시 회차와 편집기 상태 기록 |
| 파일명·저장 상태·실패 사유 | 전체 저장 경로와 과거 다운로드 기록 |

확인 불가 에셋은 요약에 표시하되, 현재의 **진행을 막지 않는 정책**을 유지한다. 게시 도중 실패하더라도 이미 생성·저장된 영상 파일의 결과는 볼 수 있게 한다.

## 3. 버튼과 진행 상태

**현재 필요한 주요 버튼은 한 곳에 하나만 표시한다.**

- 주요 버튼은 채움색·명확한 테두리·48px 이상 높이로 표현한다. 기존 청록색과 전체 디자인을 유지한다.
- 보조 버튼은 외곽선 스타일로 구분하고, 기록·근거는 펼치기 컨트롤로 제공한다.
- 버튼 문구는 실제 행동을 설명한다. `계속`보다 `기존 제작 상태 확인`, `실패 파일 다시 다운로드`처럼 표시한다.
- 비활성 버튼에는 활성화에 필요한 조건을 가까이 표시한다.
- 기존 수동 실행에서 검사·교체 계획·저장이 필요하면 해당 행동을 주요 버튼으로 올린다. 자동 처리 중에는 불필요한 수동 버튼을 나열하지 않는다.

진행 상태는 공통 표현을 사용한다.

- 단계 표시에는 **대기 / 진행 중 / 사용자 작업 필요 / 완료 / 확인 필요 / 실패**를 구분한다.
- 수치가 있으면 현재 작업의 진행 막대와 `%`를 표시한다.
- 수치가 없으면 불확정 진행 표시와 `에셋 검사 중` 같은 작업명을 표시한다.
- 제작 진행률을 검사·저장 단계까지 재사용하거나 전체 진행률로 환산하지 않는다.
- 원격 진행률이 100%여도 검증 중이면 `결과 확인 중`으로 표시한다.
- 업로드 성공 후 복사만 실패하면 완료 화면을 유지하고 `링크 다시 복사`를 제공한다.

## 4. 통합 버튼과 구현 경계

`InfoX 영상 제작 시작`은 다음 순서로 실행한다.

1. 필수 입력·검토 확인·한글 입력 조합 상태를 검사한다.
2. 클릭 시점에 편집기용 대기 탭을 확보한다.
3. 최신 대본 저장을 완료하고 해당 버전·설정을 전송본으로 확정한다.
4. 확정된 실행에 대기 탭을 연결하고 제작을 시작한다.
5. 기존 자동 제작·검사·교체·저장·검증 흐름을 추적한다.

실패와 복구는 다음처럼 처리한다.

- 저장 실패·버전 충돌이 있으면 제작을 시작하지 않는다. 실패 시 이번 클릭으로 연 대기 탭만 닫는다.
- 팝업 차단은 제작을 막지 않고, 편집 단계에 수동 열기를 제공한다.
- 응답이 불명확하면 기존 실행을 확인한다. 같은 제작 시작 요청을 자동 재전송하지 않는다.
- 새로고침으로 확정 상태만 복원한 경우에는 **확정본으로 제작 계속**을 명시적으로 눌러야 시작한다.
- 이미 진행 중이거나 완료된 실행이 반환되면 기존 상태를 표시한다.
- 실행에 사용한 확정본과 현재 편집본이 다르면 이를 표시하고, 기존 실행의 입력은 변경하지 않는다.

**백엔드 API·저장 형식은 유지한다.** 프런트엔드에 단계·상태·현재 행동·진행률을 계산하는 공통 표시 모델을 추가한다. 제작·게시·다운로드의 기존 실행 조건은 그대로 사용한다.

화면 레이아웃이 본문과 주요 버튼 영역을 함께 구성하도록 분리하되, 접기나 단계 이동 때문에 게시·다운로드 컨트롤러가 해제되거나 요청이 다시 실행되지 않도록 한다.

구현 순서는 **상태 모델과 통합 실행 → 단계형 레이아웃 → 상세 정보 접기와 진행 표시 → 회귀·화면 검증**으로 한다.

## 5. 검증과 완료 기준

- 통합 버튼 한 번으로 최신 대본 저장·확정·제작이 순서대로 실행되고, 중복 클릭은 차단된다.
- 저장 실패, 버전 충돌, 응답 유실, 새로고침, 팝업 차단에서 중복 제작이 발생하지 않는다.
- 자동·수동 실행, 확인 불가 에셋, 게시 실패, 복사 실패, 일부 다운로드 실패에서 필요한 조치가 노출된다.
- 접기·펼치기와 폴링 중에도 입력값·포커스·진행 추적이 유지된다.
- 1366×768 PC 화면에서 현재 핵심 정보와 주요 버튼을 찾기 위해 장면별 기록을 스크롤할 필요가 없다.
- 동일한 완료 데이터를 사용한 390px 화면에서 **InfoX 영역의 기본 펼침 높이를 기존 대비 60% 이상 줄이는 것**을 목표로 한다.
- 320px 화면, 200% 확대, 키보드 조작, 상태 알림과 포커스를 검증한다.
- 기존 프런트엔드 테스트·타입 검사·빌드와 외부 호출을 대체한 흐름 테스트를 통과한다.

이번 범위는 GUI와 통합 버튼의 연결 동작이다. 제작 설정·에셋 선택 정책·일부공개 게시 정책은 유지한다. 현재 계획은 첨부 화면과 로컬 코드에 근거하며, 계획 수립 중 실제 제작·업로드는 실행하지 않았다.
