# InfoX QA: 길이별 에셋 배치 및 렌더 완료 3종 다운로드

## 확정 요구사항

- 대체 대상별 배치 수는 30fps 기준 `ceil(slot_frames / 180)`이다. 6초까지 1개, 12초까지 2개, 18초까지 3개이며 경계 초과 때만 증가한다.
- 신규 실행은 `중국 대만 반도체` 즐겨찾기에서 무작위로 서로 다른 파일을 선택한다. 후보를 모두 사용한 후에는 같은 순서로 순환한다. 후보가 1개면 반복하고, 0개면 확인 필요로 처리한다.
- 구간을 정수 프레임으로 균등 분할해 합계를 보존하고 최대 차이는 1프레임으로 한다. 배정 길이를 재생할 수 없는 후보를 늘이거나 속도를 바꾸지 않는다.
- 재시도 시 전체 선택과 순서를 보존한다. 기존 단일 에셋 기록을 소급 변경하지 않는다.
- 렌더 완료 검증 직후 대본·직렬화 원문·영상을 사용자 기본 다운로드 폴더에 개별 자동 저장한다. 수동 3종 요청은 기존 업로드 완료 조건을 유지한다.
- 기존 수동 원문·대본 버튼의 호버 문구는 `마지막 렌더링 단계에서 자동으로 다운로드됩니다.`이며 클릭 동작은 유지한다.

## 구현 단위

1. 선택·변환·저장: 대상당 하나의 `ReplacementChoice`를 유지하고 하위 `ReplacementClip` 목록에 후보·프레임·결과 위치를 고정한다. 새 실행에만 `random_six_second_sequence` 정책을 설정하고 기존 `first_usable_reuse` 기록은 기존 변환기로 처리한다. 다중 클립은 `MediaLayer.image_files`로 확장하고 비대상 항목을 보존한다. 저장 전·후 모든 클립의 참조와 결과 위치를 검증한다.
2. 다운로드: 기존 자동 훅과 3종 파일 저장기를 연결한다. 서버가 자동 요청 기원을 기록해 업로드 전 부분 실패 재시도를 허용한다. 기존 자동 영상 기록은 재사용하되 소급 보충하지 않는다. 실패가 게시 처리를 막지 않게 한다.
3. UI·문서: 대상 수·클립 수·서로 다른 에셋 수·후보 부족을 표시한다. 신규 자동 3종과 과거 자동 영상 기록을 구분한다. 버튼 툴팁과 다운로드 안내를 갱신한다.

## 검증

- 6·12·18초 및 전후 1프레임, 후보 5개 중 무작위 선택, 후보 초과 순환, 후보 0·1·2개, 길이 부족, 파일 중복, 저장 선택 유실을 검사한다.
- 혼합 미디어 배열 확장 후 비대상 항목·레이아웃·음성·장면 시간 보존, 저장 후 전 클립 대체 이력과 재검사를 확인한다.
- 업로드 전 자동 3종 저장, 두 차례 부분 실패 재시도, 기존 파일 보존, 이전 기록 복원, 중복 방지와 수동 요청 제한을 검사한다.
- Python·프런트엔드 회귀 테스트, 프런트엔드 빌드, 모의 API 브라우저 smoke와 diff 검사를 수행한다. 실제 외부 생성·렌더·업로드는 실행하지 않는다.
