# 영상 자동 저장 및 3종 개별 다운로드

신규 게시 회차의 렌더 완료를 검증하면 **대본·직렬화 원문·MP4 총 3개 파일**을 ZIP 없이 사용자 기본 다운로드 폴더에 자동 저장합니다. 업로드 완료를 기다리지 않습니다. 다운로드는 게시 처리와 독립적이며 실패해도 유튜브 업로드가 계속됩니다. 새로고침·재시작은 과거 자동 다운로드를 시작하지 않으며, 기존 영상 단독 기록도 3종으로 소급 실행하지 않습니다.

업로드 완료가 검증된 현재·이전 회차에서 **대본·원본·영상 3개 파일 다운로드**를 누르면 ZIP 없이 개별 파일 3개가 같은 폴더에 저장됩니다. 기본 이름은 게시 기준일의 `YYMMDD_대본.txt`, `YYMMDD_원본데이터.txt`, `YYMMDD_영상시황.mp4`입니다. 기존 파일은 보존하고 이름이 겹치면 ` (1)`, ` (2)`를 붙입니다. 자동 저장 영상이 있어도 수동 3종 요청은 새 파일을 저장합니다.

대본은 InfoX 전송 시 GUI 확정본인 실행 스냅샷을 사용합니다. 이후 GUI·InfoX 편집은 포함하지 않습니다. 원본은 같은 실행의 직렬화 원문입니다. 날짜·영상은 선택한 게시 회차에 연결되므로 과거 회차 다운로드도 현재 최신 영상으로 바뀌지 않습니다.

Windows Known Folder API가 반환한 기본 다운로드 폴더를 사용하며 브라우저 설정과 별개입니다. 쓰기 실패 시 다른 경로로 저장하지 않습니다. 파일별 실제 경로·크기·SHA-256을 보관합니다. 재시도는 완료 파일의 존재·내용을 확인해 정상 파일을 보존하고 실패·중단·유실·변경 파일만 저장합니다. 서버 중단 시 자동 재개하지 않고 확인 필요 상태를 표시합니다.

단계형 InfoX 화면에서는 현재 회차의 다운로드 영역을 한 곳에만 둡니다. 업로드 완료가 검증되면 ④ 완료 단계에, 그 전(렌더 완료 3종 자동 저장, 게시 실패·확인 필요 포함)에는 ③ 편집 및 게시 단계에 표시합니다. 이전 회차는 ‘이전 게시 회차’ 목록 안에 회차별로 표시합니다.

‘직렬화 원문 다운로드’와 ‘압축 결과 다운로드’ 버튼은 기존 수동 동작을 유지하며, 마우스 호버 시 **마지막 렌더링 단계에서 자동으로 다운로드됩니다.** 문구를 표시합니다. 수동 대본 다운로드는 최신 GUI 저장본이며, 렌더 후 자동 대본 다운로드는 해당 제작에 보낸 확정본입니다.

## API

- POST `/api/infox-publications/{publication_id}/downloads`: `{intent_id,kind:"video"|"all"}`. HTTP 202와 작업 기록을 반환합니다.
- GET `/api/infox-publications/{publication_id}/downloads`: `{downloads:[...]}`. 조회만 수행합니다.
- POST `/api/infox-downloads/{download_id}/retry`: `{intent_id}`. HTTP 202와 재시도 작업 기록을 반환합니다.

렌더 검증 전 요청, 업로드 검증 전 **수동** 3종 요청은 HTTP 409입니다. 내부 자동 3종 요청과 그 기록에서 파생된 재시도는 렌더 검증 후 허용합니다. 재시도에는 서버가 보관한 `automatic_origin`을 사용하며, 클라이언트는 자동 여부를 지정할 수 없습니다. 같은 intent는 동일 작업을 반환합니다. 같은 회차의 다운로드가 진행 중이면 해당 작업을 반환합니다. 게시 상태·CAS·클립보드·재렌더 로직은 다운로드 상태로 변경하지 않습니다. 인증정보·서명 URL은 작업 기록에 저장하지 않습니다.

자동 영상 저장 중에 3종 요청이 겹치면 기존 영상 작업을 표시하고, 완료 후 3종 버튼을 다시 누르도록 안내합니다. 접수 응답이 유실되면 요청 UUID를 보관하며 ‘다운로드 접수 다시 확인’에서만 같은 요청으로 확인합니다. 새로고침은 다운로드 POST를 자동 재전송하지 않습니다.

다른 요청의 파일 저장이 진행 중일 때 렌더 후 자동 3종 저장이 도착하면, 자동 요청을 별도 `queued` 기록으로 보관합니다. 진행 중인 저장이 끝나면 트랜잭션으로 실행 권한을 확보해 시작하며 게시 처리는 기다리지 않습니다. 서버가 중단되면 대기 기록도 확인 필요로 전환하고 명시적 재시도를 기다립니다.
