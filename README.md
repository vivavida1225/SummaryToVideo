# Market Brief — 로컬 시황 압축

HTML 시황을 장면별 평문으로 변환하고 Gemini로 1분 영상용 5줄 낭독 대본을 만드는 Windows 앱입니다. Vue3 화면과 Python 서버가 함께 실행됩니다.

## 실행

새 컴퓨터에서는 먼저 **`install.cmd`**를 실행해 의존성을 준비할 수 있습니다. Node.js·Python을 미리 설치할 필요는 없습니다.

- 프로젝트 전용 Python 3.14.7과 Node.js 24.21.0의 설치 여부·버전을 확인하고, 없거나 버전이 맞지 않으면 다운로드하여 설치합니다.
- Python 가상 환경과 `requirements.txt` 패키지, 프런트엔드 npm 패키지를 준비하고 필요한 경우 화면을 빌드합니다.
- 런타임은 `.tools/`, Python 패키지는 `.venv/`, 프런트엔드 패키지는 `frontend/node_modules/`에 설치됩니다. 시스템에 설치된 Node·Python이나 전역 PATH는 변경하지 않습니다.
- 최초 설치에는 인터넷 연결과 프로젝트 폴더 쓰기 권한이 필요합니다. 정상적으로 준비된 항목은 재사용하므로 다시 실행해도 됩니다.
- 설치만 진행하며 앱 서버·브라우저를 시작하거나 Gemini API를 호출하지 않습니다. 완료 후 아래 순서대로 `start.cmd`를 실행하세요.
- 오류가 나면 `.runtime/launcher.log`를 확인하세요. 더블클릭 실행 시 결과 확인을 위해 창이 대기합니다. 터미널·자동화에서는 `install.cmd --no-pause`를 사용하며, 성공은 종료 코드 0, 실패는 0이 아닌 값입니다.

`start.cmd`도 동일한 자동 준비 기능을 사용하므로 별도 설치 단계를 생략하고 바로 실행할 수 있습니다.

1. 탐색기에서 **`start.cmd`**를 실행합니다. 준비가 끝나면 기본 브라우저가 열립니다.
2. 기본 입력은 클립보드의 HTML입니다. **클립보드 다시 읽기**, 직접 붙여넣기, 또는 **저장된 파일** 선택을 사용할 수 있습니다. 파일은 미리 선택하지 않습니다.
3. **변환 및 1분 압축**을 누릅니다. 직렬화 결과가 자동 복사되고, Gemini 응답이 검증을 통과하면 최종 대본이 다시 자동 복사됩니다. 검증 실패 대본은 경고와 함께 표시되며 수동으로 복사·다운로드할 수 있습니다.
4. 사용을 마치면 **`stop.cmd`**로 서버를 종료합니다. 브라우저 탭만 닫으면 서버는 계속 실행됩니다.

최초 환경 준비에는 인터넷 연결이 필요합니다. 화면과 HTML 변환은 로컬에서 동작하며, 압축할 때 직렬화된 뉴스 본문을 Gemini로 전송합니다. 화면을 여는 것만으로 API를 호출하지 않습니다.

## API 키와 결과

- 프로젝트의 기존 `.env`에서 `GEMINI_API_KEY_1`, `GEMINI_API_KEY_2`, `GEMINI_API_KEY_3`을 읽습니다. 빈 키는 건너뜁니다. 새 환경이라면 `.env.example`을 `.env`로 복사한 뒤 값을 입력합니다.
- 오른쪽 위 System Status의 **시작 모델** 드롭다운에서 모델을 선택합니다. 기본값은 `gemini-3.8-flash`이며 목록 순서는 Gemini 3.8 Flash → Gemini 3.7 Flash → Gemini 3.6 Flash → Gemini 3.5 Flash-Lite입니다. API ID는 각각 `gemini-3.8-flash`, `gemini-3.7-flash`, `gemini-3.6-flash`, `gemini-3.5-flash-lite`입니다.
- 선택한 모델부터 목록 아래쪽으로만 폴백합니다. 예를 들어 3.7을 선택하면 3.7 → 3.6 → 3.5 Flash-Lite 순서입니다. 선택값은 같은 브라우저·앱 주소의 `localStorage`에 저장되어 새로고침·재접속 시 복원되며, 저장값이 없거나 지원하지 않는 값이면 3.8로 시작합니다. 브라우저 저장소가 차단되면 현재 화면에서만 선택값을 유지합니다.
- 작업 중에는 모델 선택을 잠급니다. 자동 폴백은 저장된 시작 모델을 바꾸지 않으며, 진행 패널에는 실제 호출·응답 모델과 전환 사유를 표시합니다. 키 값은 브라우저·결과 파일·로그에 노출하지 않습니다.
- 결과는 `outputs/<실행시각_고유ID>/serialized.txt`와 `compressed.txt`에 저장됩니다. `compressed.txt`에는 검증 실패 대본도 보관될 수 있으므로, 성공 여부는 화면의 경고 또는 `metadata.json`의 상태·오류를 확인하세요. 메타데이터에는 시작 모델(`requested_model`), 현재·마지막 호출 모델(`model`), 시도한 모델 목록(`attempted_models`)과 시도 횟수도 남습니다.
- 각 비어 있지 않은 API 원응답은 `raw_response_N.txt`에 보관합니다. 검증에 실패한 원응답은 `invalid_response_N.txt`에도 보관합니다. `N`은 API 호출 시도 번호입니다.
- 자동 저장에 실패해도 생성된 결과는 현재 화면에서 다운로드할 수 있습니다. 서버를 종료하기 전에 다운로드하세요.
- 정상 결과 파일은 UTF-8, LF 개행의 본문을 저장합니다. Windows 클립보드에는 같은 본문을 Windows 개행으로 복사합니다. 진단용 API 원응답에는 모델이 출력한 구분자나 잘못된 형식도 그대로 남습니다.

화면의 다운로드 버튼은 **작업 생성일의 한국 시간(Asia/Seoul)**을 기준으로 파일명을 지정합니다. 과거 작업을 다시 다운로드해도 해당 작업의 생성일을 사용합니다.

| 다운로드 대상 | 파일명 | 예시 |
| --- | --- | --- |
| 직렬화 원문 | `YYMMDD_원본데이터.txt` | `260911_원본데이터.txt` |
| 압축 결과·검증 실패 대본 | `YYMMDD_대본.txt` | `260911_대본.txt` |

서버의 실행별 폴더에는 기존 이름인 `serialized.txt`와 `compressed.txt`로 저장됩니다.

## 오류 처리

호출 한도(429), 서버 오류(5xx), 408, 연결 오류·타임아웃, 빈 응답, 모델 없음·사용 불가(404)는 **같은 키로 다음 모델**을 즉시 호출합니다. 실패한 모델로 돌아가지 않고, 마지막 후보까지 실패하면 종료합니다. 기존 모델의 재시도 대기 지시는 다른 모델로 넘어갈 때 적용하지 않습니다.

`API_KEY_INVALID` 또는 인증/권한 오류(401·403)는 **같은 모델에서 다음 키**로 전환합니다. 실패한 키는 해당 작업에서 다시 쓰지 않으며 모든 키가 소진되면 종료합니다. 같은 프로젝트의 여러 키는 호출 한도를 공유하므로 쿼타 오류에서는 키를 순회하지 않습니다.

호출 상한은 **후보 모델 수 + 설정된 키 수 − 1 + 보정 1회**입니다. 3.8부터 시작하고 키가 1개면 최대 5회입니다. 요청당 **60초**, 전체 **300초** 제한을 유지하므로 남은 시간이 없으면 후보나 보정 횟수가 남아도 종료합니다. 작업을 시작할 때 모델과 키 목록을 확정하며 SDK 내부 자동 재시도는 사용하지 않습니다.

구분자·형식·문장·지수·분량 검증 실패에는 **최대 한 번** 보정 요청을 합니다. 확인 가능한 여러 위반을 함께 수집하여 최초 입력 원문, 이전 API 원응답, 변환 후 줄 수·글자 수, 부족·초과 분량과 장면 작성 규칙을 전달합니다. 보정은 같은 모델·키에서 시작하며, 통신 오류로 폴백하면 이 보정 문맥을 다음 모델로 전달합니다. 두 번째 검증 실패에서는 종료합니다.

보정 후에도 실패하면 작업 상태는 실패로 유지하고, 진행 상황 영역의 기존 위치에 경고를 표시합니다. 마지막 응답은 정상 대본과 같은 article 결과 패널에 **검증 실패 대본**으로 표시합니다. 명시된 장면 구분자는 개행으로 변환하며, 이 변환 결과를 `compressed.txt`에 저장하고 화면·수동 복사·다운로드에 공통 사용합니다. 실패 대본은 자동 복사하지 않습니다. 저장된 오류에는 내용 검토가 필요한 부분이 모두 포함되는 것은 아닙니다.

일반 요청 설정 오류(400 등)와 명시적인 생성 차단은 자동 재시도하지 않습니다. 폴백이 모두 실패하면 마지막 오류와 시도한 모델을 표시합니다. 보정 중 통신 오류로 종료되어도 마지막 초안은 수동 복사·다운로드할 수 있고 자동 복사하지 않습니다. **압축 다시 시도**는 현재 드롭다운의 모델과 원래 직렬화 결과를 사용하며 클립보드나 원본 파일을 다시 읽지 않습니다.

클립보드가 다른 프로그램에 잠겨 있으면 경고를 표시하고 다음 단계를 계속합니다. 결과의 복사 버튼으로 다시 복사할 수 있습니다.

## 입력 형식

`src` 아래의 `.txt` 또는 `.html` 파일을 선택할 수 있습니다. 파일은 UTF-8 또는 UTF-8 BOM이어야 하며 최대 5 MiB입니다. 클립보드는 HTML 소스 텍스트와 Windows HTML clipboard format을 지원합니다.

HTML에는 `<header>`를 포함하는 실제 뉴스 `.embedded-content`가 하나 있어야 합니다. `.summary-box`, `.summary`, `.indices/.index-card`, `section/h2`, `ul/li`의 `.key-info`와 `.key-detail`을 순서대로 변환합니다. 누락·중복 구조는 오류로 표시합니다. 참고 입력은 `src/0910/0910_html.txt`입니다. `src/0907/1.txt`는 이미 평문인 참고 자료여서 HTML 변환 입력으로는 사용할 수 없습니다.

기존 `prompts/html to input text.txt`의 명시된 규칙을 Python으로 구현했습니다. 입력 직렬화의 장면 구분자는 항상 `===`입니다. `prompts/compress_to_1min.txt`는 API 요청마다 다시 읽고 5줄 대본 출력 계약을 덧붙입니다. 편집 내용은 다음 호출에 반영됩니다.

## 대본 생성과 검증

압축 결과는 코드블록·번호·제목 없이 정확히 5줄입니다. 각 줄은 본문 1~2문장이고, 첫 줄의 “오늘의 AI 시황입니다.”와 마지막 줄의 “오늘의 AI 시황이었습니다.”는 문장 수에서 제외합니다. 인사말은 본문과 같은 줄에 둡니다.

API에는 실제 줄바꿈이나 문자 그대로의 `\n` 대신, 5개 장면 사이에 `<SCENE_BREAK>` 구분자를 정확히 4개 출력하도록 요청합니다. 백엔드는 구분자 주변 공백을 정리하고 이를 개행으로 변환한 뒤 검증합니다. 화면·저장·복사·다운로드는 같은 변환 결과를 사용합니다. 구분자는 글자 수에서 제외합니다. 구분자 수 오류·빈 장면·장면 내부 개행은 보정 대상이며 경계를 추정하거나 문장을 임의로 재배치하지 않습니다. 기존 정상 5줄 응답도 허용합니다.

5줄은 시장 결과·장중 경로 → 외부 변수 → 주도 업종·주도 수급 → 투자주체별 수급·리스크 → 오늘 시장 정의·다음 장 체크포인트 순서입니다. 프롬프트는 시청자가 기억할 핵심 세 가지를 먼저 선택하도록 안내합니다.

최초 작성과 보정 모두 약어·기업명·상품명 등 고유명사를 사용할 때 원문의 표기를 유지하도록 지시합니다. 자연스러운 낭독 문장은 문장 구조와 연결 표현으로 다듬으며, 영문 약어를 발음대로 한글로 변환하거나 다른 약어로 바꾸지 않습니다. 수치의 대상·기간·단위·범위도 유지합니다. 예를 들어 전체 수출 350억 달러를 반도체 수출 350억 달러로 바꾸지 않도록 합니다. 이는 모델에 전달하는 작성 규칙이며, 현재 자동 검증기가 모든 약어·고유명사·일반 수치의 의미를 대조하는 것은 아닙니다.

문장 수, 인사말 위치, **490~550자 범위** 및 첫 줄의 지수별 종가·등락률·방향을 검사합니다. 목표는 500자이며, 하한 미달과 상한 초과 모두 보정 대상입니다. 천 단위 쉼표 차이, `%`와 ‘퍼센트’ 표기, `0.00%`의 ‘보합’ 표현은 허용합니다. ‘급락·폭락·내림세’, ‘급등·폭등·반등·오름세’도 등락 방향으로 인식하며, 입력과 반대 방향이면 거부합니다. 글자 수에는 인사말·숫자·공백·문장부호를 포함하고 개행만 제외합니다. 자료 부족도 하한 검증의 자동 예외는 아니며, 사실을 지어내 분량을 채우지 않도록 지시합니다. 검증은 서술 전체의 사실성·인과관계를 보증하지 않으며, 내용의 충실성과 인포엑스 TTS 아나운서 ‘빠름’ 설정에서의 실제 낭독 시간은 최종 편집 단계에서 확인하세요.

새 출력 계약은 새로 생성하는 결과에 적용하며, 기존 저장 결과를 새 규칙에 맞춰 재작성하지 않습니다. 이전 검증 실패 기록에 `compressed.txt`가 없으면 마지막 `invalid_response_N.txt`를 불러와 표시·복사·다운로드할 수 있습니다. 해당 원응답에 명시적 장면 구분자가 있으면 조회 시 개행으로 변환하고, 과거 파일 자체는 수정하지 않습니다.

프롬프트 파일 수정은 다음 API 요청에 반영됩니다. 백엔드 코드나 앱 출력 계약·보정 지시 변경 후에는 `stop.cmd`로 종료하고 `start.cmd`로 다시 실행하세요. 프런트엔드 변경은 빌드가 필요하며, `install.cmd` 또는 종료 후 `start.cmd`로 준비한 다음 브라우저를 새로고침하세요.

## 개발 및 검증

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
$env:PATH = "$PWD\.tools\node;$env:PATH"
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
```

Python 직렬화만 실행할 수 있습니다.

```powershell
.\.venv\Scripts\python.exe -m backend.serializer src/0910/0910_html.txt -o result.txt
```

`--fenced`를 추가하면 하나의 `text` 코드블록으로 감싼 출력을 생성합니다.
